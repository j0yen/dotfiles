# Account exhaustion lanes (A1300/A1301)

Policy data: `.config/account-lanes/policy.json`. Tool: `.local/lib/account-lane.py`. Launcher: `.local/bin/fable-launch.sh`. Test: `tests/account-lanes.test.sh`.

- Lanes are per account and per model class: `fable` and `nonfable`. State = `~/.local/state/account-lanes/{state,sessions}.json` (+ `events.jsonl` audit), one flock, atomic replace.
- Fable: `jyen.pm`, then `mcphost.dev` only after jyen.pm's Fable lane is exhausted. Non-Fable: `josephsyen`, `jyen.tech` (exhausted ones skipped); `jyen.pm` only when BOTH are exhausted. `mcphost.dev` never serves non-Fable. jyen.pm Fable exhaustion never disables its non-Fable lane.
- Exhaustion is established only by the CLI's quota message as a WHOLE trusted message: exactly `You've hit your (session|usage|weekly) limit` optionally followed by ` · resets <time>`. OBSERVED wording (saved local CLI transcripts, sanitized in `tests/fixtures/account-lanes/`): `You've hit your session limit · resets 8:20am (America/Los_Angeles)` and `You've hit your weekly limit · resets Nov 2, 8pm (America/Los_Angeles)`, carried as a synthetic assistant message with `isApiErrorMessage:true` and `error:"rate_limit"` (the same category a transient limit may use, so the category is never trusted). A phrase embedded in or quoted by other text is `unknown`. Channels: stream-json is judged only when the CLI was explicitly started with `--output-format stream-json` (the launcher carries that flag to the supervisor; duplicate/unknown values are refused; stdout content NEVER selects the parsing mode, so a JSON terminal-result-looking model answer in text/json/plain mode is ignored), and then only as a clean stream (every non-empty stdout line a JSON object) whose LAST event is the terminal `result` error event; the stream is validated INCREMENTALLY by the supervisor (`StreamObserver`): each complete line is parsed as it arrives, only the last complete event is retained, so the stream length is unbounded (memory = one event line); there is no raw byte tail inference. Any corrupt, non-JSON, non-object or oversized (> 8 MiB per event line, `max_event_line()`, cannot be validated) line anywhere makes the whole stream untrusted with an explicit `account-lane: stream evidence: ...` reason (unknown, no state change); an oversized terminal line is therefore unknown, never a silent success. An observer or parse failure of any ordinary `Exception` (e.g. `RecursionError` on a deeply nested line) never escapes into the output pump: the stream becomes sticky-untrusted with a sanitized reason (exception class only, no event text), stdout/stderr keep draining and forwarding byte-for-byte, the child's rc is preserved, and a failed observer never produces quota state. `BaseException` (shutdown signals) is not caught. Chunk/newline/CRLF/multibyte splits do not matter (bytes are line-assembled before decoding); plain text only from stderr when it is exactly one line (stdout is the model-output channel and is NEVER judged as plain text, not even an exact bare phrase with a non-zero rc: a real plain `claude -p` quota channel has not been observed, so plain stdout quota detection is unsupported); a killed/timed-out run (signal, rc 124, rc > 128) yields no plain-text evidence at all. Rate-limit/overload, context limits, spend/monthly/budget caps, paid prompts, auth, network, mixed and unrecognised text change nothing (`unknown` = rc 4, visible). The lane is trusted launch metadata (`--lane`/`--model`). Text is never stored. NOT observed, therefore not accepted: a stream-json quota failure event, plain `claude -p` quota output, "5-hour"/"Opus"/org monthly wording, the `usage limit reached|<epoch>` form. This is an open acceptance item until the canary captures them.
- Reset: a strict future epoch from a trusted caller (`--reset-epoch`, e.g. seat-tick `quota_wait_until`; <= 35 days) or a `resets <time>` text form auto-expires the entry (audited `reset_expired`). The legacy `usage limit reached|<epoch>` suffix was never observed, so it is NOT trusted (unknown, no state). Malformed/past/out-of-range resets stay unknown and never clear or shorten an exhaustion. No reliable reset = stays until audited `clear --by X --reason "..."`.
- Select/launch with no usable account = structured JSON block on stdout, exit 75; malformed state/policy = exit 76. Neither switches accounts.
- Sessions: every launch is claimed under one lock (fresh = select + claim atomically; resume = validate). `--resume` of an UNMAPPED session blocks (`session_unmapped`, safe_boundary); explicit adoption needs `FABLE_LAUNCH_ADOPT_ACCOUNT/BY/REASON`, a prior `launch` row naming that session and account in the decision log, a lane-permitted account, and still the unknown-effect ack; audited `session_adopted`. A mapped resume is pinned to its recorded account while usable, else `account_transfer_unsupported`; Fable<->non-Fable is `model_switch_unsupported`. A session is `clean` only after the supervisor observed exit 0 AND nothing independently flagged it unknown while it ran (exhaustion evidence tagged with the session, or `account-lane.py session-mark-unknown --by --reason`): success never erases that signal. Any non-zero/signalled exit, a dead unfinished claim (supervisor killed, interrupted interactive claim) or exhaustion leaves it not-clean: resume needs `FABLE_LAUNCH_ACK_UNKNOWN_EFFECT=<why>` (exit 77 otherwise, audited) and is never replayed automatically. Liveness = pid + /proc starttime.
- Supervision: every fable-launch.sh run is a child of `account-lane.py run` (no exec of claude): headless passes streams through and classifies a failure; interactive (`--tty`) inherits the terminal. Signals sent to the supervisor itself (`kill -INT/-TERM/-HUP/-QUIT <pid>`) are collected with `sigtimedwait` and forwarded to the child (audited `signal_forwarded`), including when the launcher inherited SIGINT as ignored (nohup/`&`; the child then gets its original disposition back). A terminal ^C is delivered by the kernel to the whole foreground group, so the supervisor does not forward it a second time. Unsupported (declared, not faked): SIGSTOP/SIGTSTP/SIGCONT sent to the supervisor alone (job control of the supervisor and child separately), SIGWINCH is delivered by the terminal to the child directly. Any non-clean ending marks the session unknown_effect. Interactive exhaustion is NOT observable; interactive completion is.
- Credentials: only the selected account's OAuth token is exported; inherited `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, Bedrock/Vertex/Foundry switches are scrubbed (names reported, never values). No API/paid path exists.
- Native child agents inherit the parent token (unsupported to change): `fable-native-agent-guard.sh` now treats `mcphost.dev` like `jyen.pm` (non-Fable child denied; Fable child needs effort high).
- Callers: `fable-launch.sh`, `fable-review.sh` (default path now via the launcher), `ctl-launch.sh --account`, `ctl-account-follow.sh`, `fleet-token-rotate.sh` (+ `--check`), `fleet-token-429-watch.sh` (candidate filter + structured nonfable record). Gate states (`account-lane-gate.sh`, shared by rotate, watcher, ctl-launch, ctl-account-follow): `enforced` (policy readable), `broken` (the lane tool `~/.local/lib/account-lane.py` or `~/.config/account-lanes/` exists, or a named policy path is unreadable, but no readable policy) = REFUSE with a WARNING that names the fix, and `legacy` (neither tool nor policy installed) = behaviour unchanged. A removed or unreadable policy.json is therefore never a silent disable; the reviewed rollback is restoring the previous scripts together with removing the tool.  The watcher stays disarmed past its EXPIRES; nothing here arms it.
- Unsupported / not observed: no real quota endpoint or message was called or captured; limit-message wording is the existing watcher's pattern, tested with SYNTHETIC text only. Interactive (non -p) launches exec claude and cannot observe exhaustion; they rely on the watcher/operator calling `record`.

## Installed compatibility (A1221 round-robin, pins, f8fe)
- Fresh non-Fable launches keep the installed round-robin over the primaries (josephsyen, jyen.tech): slot `n % 2`, exhausted primaries skipped, jyen.pm reserve only when both are exhausted. The counter now lives in the lane state (`rr.json`, same lock as selection and claim), advances only with a claimed allocation, and `session-abort` (missing credential, exit 66) gives the slot back, so a missing credential never rotates and never falls back. A Fable launch never moves the slot.
- A resumed SID stays pinned to its recorded account. A pre-lane SID has no `sessions.json` entry (blocks `session_unmapped`); the installed `$HOME/.cache/aide/account-rr/sid-map` record (non-Fable resumes only) is offered as an audited adoption (`installed-rr-sid-map`) which still needs a prior `launch` row in the evidence log, a permitted account and the unknown-effect ack. `--session-id=<id>` is parsed like `--session-id <id>`. `FABLE_RR_DIR` is a test seam, refused in production.
- The installed duplicate-guard exclusion `!/fable-launch/` is NOT adopted: the ancestor-aware guard plus the atomic pid+starttime claim replace it without leaving a launcher-shaped process undetected.
- `fable-review.sh` defaults to `$HOME/.local/bin/fable-launch.sh` (installed), else the sibling launcher; `fable-native-agent-guard.sh` keeps the installed pool wording and the mcphost.dev rule.
- Rollout: the canary secrets/store must hold a credential for each account a canary run can be allocated (a second fresh non-Fable session lands on jyen.tech).

## Observed native Fable-limit contract
OBSERVED (saved native output of a real bridge run, `tests/fixtures/account-lanes/native-fable-limit-observed.json`): a terminal `result` with `is_error=true`, `terminal_reason=api_error`, `api_error_status=429`, `api_error=model_requires_usage_credits`, empty `modelUsage`, and the exact text "You've reached your Fable limit. Switch to another model, or manage usage credits at https://claude.ai/settings/usage?from=cc_cli_limit_message, to continue.". It retires the Fable lane of the launch account ONLY when: the launch lane is `fable` (from the selected model, never from output), the account is permitted, the CLI was started with `--output-format json` (stdout is exactly one JSON object) or `stream-json` (clean stream, that event last), the exit is a plain non-zero rc (not killed/timed out), and every field above matches exactly. 429 alone, another `api_error`, generic credit/spend/overage wording, a different text, a model that produced usage, a non-Fable lane/model, a model-authored or quoted event, malformed/mixed/truncated/multi-object output and plain/text stdout never qualify (unknown, no state change). No reset time is in the message, so none is invented: the lane stays exhausted until an audited `clear`.
Session id: under `--no-session-persistence` the supervisor key never reaches the CLI, so the native `session_id` legitimately differs. The audit event `native_fable_limit` records `claimed_session`, `native_session_id` and `sid_correlation` ("none ..." / "matches ..."); the claimed session stays unknown-effect and the native id is never mapped, adopted or used to clear anything. If a session id WAS passed to the CLI and the envelope carries a different one, the run is not accepted (safe block, no state). Native in-session account/model transfer remains unsupported.

### Native SID hardening (observed contract)
When a session id was actually handed to the CLI (injected, `--session-id X`, `--session-id=X`, `--resume X`, also together with `--no-session-persistence`) the native result must carry exactly that id: a missing, null, empty, non-string or different `session_id` fails closed (no lane write, the claimed session stays unknown-effect, nothing adopted or replayed). Only a truly unpinned `--no-session-persistence` run (no id reaches the CLI) is recorded from the supervisor-owned child's own output, with the audit stating `sid_correlation: none ... unpinned` and the uncorrelated native id. The separate audit-lock note (finding 3: `exhausted` and `native_fable_limit` rows are written in two lock sections, a crash between them loses only the native row) is unchanged and cosmetic.

## Observed non-Fable terminal envelope

For a NONFABLE launch (lane from the selected model) read from the CLI's own `--output-format json` / `stream-json` channel with a plain non-zero exit, that envelope exhausts only the selected account's nonfable lane; the ordinary classifier still rejects auth/network/spend/mixed text, reset parsing is unchanged. `is_error` must be exactly `true` and the status a numeric `429` (not bool/string/float). Not independently captured: launching argv, exit code value, account, stderr bytes, stream-json form. The Fable `model_requires_usage_credits` contract and the legacy fixture-era policy are unchanged.

### Nonfable stream-json has no weaker fallback
For a nonfable launch with `--output-format stream-json`, stdout can record exhaustion only through the observed-shape gate (`type=result`, `is_error` true, numeric 429, `terminal_reason=api_error`, anchored message, exact session id when one was passed, plain non-zero exit). A refused terminal event stays unknown with state and audit untouched; only the trusted one-line stderr message can still apply. The stream form itself is unobserved (the real fixture is json); stream terminals in tests are synthetic. A refusal prints one "not accepted" reason and one `failure classified unknown` line; an accepted contract prints a single classification line. The Fable lane's stream-json anchored path is unchanged (outside this repair).
